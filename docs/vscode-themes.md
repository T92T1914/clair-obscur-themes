# Clair and Obscur for Visual Studio Code

The 0.1.0 candidate puts both appearances in one local color-theme extension. Clair uses the shared warm light canvas. Obscur uses the shared near-black canvas. The extension maps the existing semantic palette onto the editor, navigation, tabs, controls, focus indicators and syntax colors.

The extension is declarative. It contains no executable entry point, activation handler, runtime dependency, network code or font file. It contributes no configuration defaults and does not rewrite user settings. Selecting a theme can save the user's color-theme choice. Keep the editor's appropriate monospace font and your preferred workbench typography.

## Build the local candidate

From the repository root, with Python 3.11 or newer:

```powershell
python -m themeforge.vscode --output outputs/vscode-01
python -m themeforge.vscode --output outputs/vscode-01 --check
```

The output contains an extracted `extension/` directory, `Clair-Obscur-VSCode-0.1.0.vsix`, an identity manifest and `SHA256SUMS`. The extension directory contains `package.json`, the two color-theme JSON files and `LICENSE.txt`. The VSIX contains the same payload and its packaging metadata. Its local identifier is `T92T1914.clair-obscur`. This is a local candidate, with no Marketplace publication.

The manifest's token hash identifies the canonical JSON encoding of the validated token document. It does not identify the original whitespace or line endings of an input file. Output file hashes and `SHA256SUMS` identify the actual generated bytes.

Use a new output directory outside managed `dist/`. Existing output, including an empty directory, is preserved. Filesystem roots and linked or reparse-point paths are refused. `--check` compares the exact generated bytes and inventory without repairing changed, missing or extra entries. Keep later installation state outside this generated tree.

Build in a task-owned directory that other processes are not changing. Path checks refuse observed linked entries and unexpected subdirectories. They do not provide operating-system isolation against concurrent path replacement. A failed write preserves incomplete output for inspection.

This generator has its own version and output inventory. It leaves the accepted browser/client download tree, original family release, Garmin and Samsung packages unchanged. The current source snapshot includes the generator, its tests and this guide.

## Install, select and restore

For a first installation, use a disposable VS Code profile. Record its current color-theme selection and settings-sync state before changing anything. Do not replace an existing extension or apply account-wide settings to obtain a test result.

1. Open the Extensions view's menu and choose **Install from VSIX...**. Select the generated VSIX file.
2. Open **Preferences: Color Theme**. Select **Clair** or **Obscur** from the installed extension. The unique theme identifiers are `clair-obscur-clair` and `clair-obscur-obscur`.
3. Inspect real code, comments, selections, keyboard focus, lists, inputs, tabs and diagnostics in the languages and extensions you use. Language providers and user color customizations can affect the result.
4. Switch between both appearances. After an independently normal application restart, check the saved selection before making a repair or changing settings.
5. Restore the recorded previous theme. Uninstall the local extension if the trial is complete, then confirm the previous selection and sync state. Record any incomplete cleanup.

VS Code documents [local VSIX installation](https://code.visualstudio.com/docs/configure/extensions/extension-marketplace#_install-from-a-vsix) and [color-theme selection](https://code.visualstudio.com/docs/configure/themes). These instructions describe the supported user route. They are not a claim that installation or restoration occurred in your desktop profile.

## Palette and syntax

Workbench colors reuse the shared canvas, panel, control, text, muted, border, selection, accent and focus roles. Syntax rules distinguish comments, strings, constants, keywords, types and functions through existing palette roles. TextMate rules provide ordinary grammar coloring. Semantic token rules apply when the language provider supplies those tokens and semantic highlighting is enabled. The theme does not implement a language provider.

The implementation follows VS Code's [theme contribution contract](https://code.visualstudio.com/api/references/contribution-points#contributes.themes), [color-theme format](https://code.visualstudio.com/api/extension-guides/color-theme) and [semantic highlighting rules](https://code.visualstudio.com/api/language-extensions/semantic-highlight-guide). Host-owned geometry, font choice, language behavior and diagnostic meaning remain with VS Code and the user's extensions.

Calculated contrast checks cover the actual mapped foreground/background pairs. They do not establish every extension surface, physical display condition, color-vision result or broad accessibility conformance. Syntax-color research does not establish that this particular palette improves comprehension, productivity or eye comfort.
