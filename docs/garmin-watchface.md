# Clair and Obscur watch-face candidate

This Connect IQ watch face targets `fenix9pro47mm`, the fēnix 9 Pro 47 mm AMOLED. Version 0.8.0 adds Hybrid: analog hands and exact digital time together, a localized day/date, Weather, Steps and watch battery. Original faceted hands and indices add restrained depth within the accepted dial margin. The earlier Analog and Digital layouts retain their drawing and saved field choices. Digital keeps its Inter Bold clock resource from 0.5.0. Clair and Obscur use `tokens-monochrome.json`: white with black lettering in Clair, black with white lettering in Obscur, and neutral gray for secondary information. Earlier programs remain separate. Hybrid and Analog use the existing shifted thin analog outlines on true black in always-on mode. Digital keeps its small time-only view. A fully off display remains black.

Both 0.8.0 programs compiled for the exact target under SDK 9.2.0. All 32 annotated groups then executed and passed in that target's simulator, including Gregorian rollover, synthetic time-zone/DST conversion, formats, field choices and geometry. These tests and the first bounded normal-program observations are described below. Physical installation, watch-side fit, restoration and power use remain separate acceptance questions.

The preserved 0.4.0 normal and test-enabled programs compiled for the exact target with Connect IQ SDK 9.2.0 and device package `ee244507b073c52779d26e77dc69b690d79098bd`. The test build includes 20 annotated test groups. They have not run for 0.4.0. The separate 0.3.0 and 0.2.0 simulator results remain below. Compilation does not establish native rendering, settings persistence, runtime memory, physical-watch installation, store acceptance or battery life. Earlier local candidates and all desktop package identities remain separate.

## Supported setup

Use Garmin's [SDK download](https://developer.garmin.com/connect-iq/sdk/) and [Getting Started](https://developer.garmin.com/connect-iq/connect-iq-basics/getting-started/) instructions. Complete the official SDK Manager's private Garmin Connect sign-in, acquire SDK 9.2.0 and the exact `fenix9pro47mm` device package with fonts, and select that SDK as active. The inspected official setup does not establish a fresh noninteractive download route. Do not substitute an unofficial downloader, guessed endpoint or another device identifier.

The [command-line setup](https://developer.garmin.com/connect-iq/reference-guides/monkey-c-command-line-setup/) requires Java 11 or newer. A verified vendor runtime archive can be kept local to the build without changing system PATH. The build command below selects its Java directory for the compiler process only.

Garmin also requires an RSA 4096-bit developer key to sign compiled programs. Keep the private key outside this repository and its build outputs. Follow Garmin's key-generation instructions and retain the key privately for future updates. Do not commit, copy into a source archive or export an existing key for this build.

## Generate and compile

The palette generator maps the validated semantic roles in `tokens-monochrome.json` to Monkey C constants. It does not modify the desktop tokens or `dist/`. Explicit `--tokens tokens.json --output NEW_FILE` can generate the earlier palette colors for inspection without replacing the current generated source.

```powershell
python -m themeforge.garmin
python -m themeforge.garmin --check
python garmin/build.py --sdk C:/path/to/installed-sdk --java-bin C:/path/to/runtime/bin --key C:/private/developer_key.der --output-dir outputs/garmin-build-01
```

Use a new output directory for each build. The wrapper preserves previous output, checks the generated palette, selects only `fenix9pro47mm`, captures compiler diagnostics and records a nonempty program's checksum after a successful compiler result. Its Java process uses headless mode, limits the heap to 1 GiB and sets the JVM's active processor count to two. It does not download packages, generate keys, install an app or launch a simulator. A program's file size is not its runtime memory use.

Add `--tests` to compile the annotated Monkey C tests. That includes tests in a program without running them. Garmin's [unit-test framework](https://developer.garmin.com/connect-iq/core-topics/unit-testing/) executes in its simulator. Simulator execution requires a separately suitable environment and must not silently launch on an occupied desktop.

## Appearance and rendering

The system Watch Face configuration menu offers Appearance and Layout. The persistent `appearance` property remains 0 for Clair and 1 for Obscur, with Obscur as the default. The `layout` property preserves 0 for Analog and 1 for Digital, and adds 2 for Hybrid. Hybrid is the new-install and invalid-value fallback. Existing valid saved values are retained until deliberately changed. Analog and Digital show Left data and Right data controls. Hybrid instead shows its date-format control because its Weather and Steps fields are fixed. The legacy data properties are not overwritten. Invalid menu selections do not replace a saved choice. Choosing an item saves it and returns to the face. Back cancels the highlighted choice. Settings changes request a fresh drawing. Simulator property/menu tests have executed. The bounded normal Appearance and Hybrid date-menu observations are recorded in the [current qualification](#current-080-qualification). One independently normal SDK restart is qualified there, with physical and permanent persistence still open.

Time follows the device's 12/24-hour preference. Hybrid places AM/PM beside digital time when needed. The legacy layouts keep it on their compact calendar line. Every update captures one `Time.Moment`; numeric and localized Gregorian information come from that same moment. Hybrid uses the device/language-dependent abbreviated weekday and month, with Day Month, Month Day or an ISO date selected by the new `hybridDateFormat` property. The reviewed public API does not expose the device's date-order preference, so this does not claim to mirror one automatically. Missing localized names fall back to an unambiguous ISO date. Analog and Digital retain their compact English date. See [Gregorian.Info](https://developer.garmin.com/connect-iq/api-docs/Toybox/Time/Gregorian/Info.html) for native format semantics.

Battery percentages are truncated to whole percentages. Invalid or unavailable values display `--%`, including the explicit NaN guard retained from the earlier target defect. Hybrid uses `BAT` normally and `CHG` when `System.Stats.charging` is true. That is the supported charger-state indicator, not a measurement of charging current. It remains the watch's charge, separate from Body Battery. Garmin documents charge hysteresis and the [battery and charging attributes](https://developer.garmin.com/connect-iq/api-docs/Toybox/System/Stats.html).

At font scale 1.00, the digital layout first tries the included Inter Bold clock resource, limited to digits, colon and the invalid-time hyphen. It measures width and height before drawing. Unsupported text or a failed fit falls back to the retained native time candidates. Other font scales use native Bionic Bold time candidates, preserving the continuous platform scale instead of silently holding the bitmap size fixed. Data values retain Bionic Bold, with Roboto Medium for calendar and battery and Roboto Condensed for field labels and detail. The analog layout uses Roboto Medium for values, date and charge, with Roboto Condensed for labels and detail. The view reads the device's 0.80 to 1.35 font-scale preference and caches fonts for the selected layout only. It includes scaled platform-font fallbacks when a requested face is unavailable. Every selection measures width and height before clipped drawing. Analog information fields choose all three row fonts together so the complete group fits its smaller band. If no measured combination fits, that field stays blank. The [current qualification](#current-080-qualification) includes bounded native Hybrid font-scale and hand-crossing samples. Legacy glyph fit and unavailable-field visibility still need their own current-version native inspection. The single derived clock atlas and metrics are bundled under the included SIL Open Font License. The original TTF is not bundled. The resource is loaded once outside the update handler and remains cached, including while Analog is selected. Its loaded-memory cost remains unmeasured. Analog supporting text, settings menus and Digital always-on keep Garmin fonts. Analog always-on draws no text. This is a bounded app resource, not a watch-wide font installation.

Hybrid requests native Bionic Bold for digital time and Roboto for the date and fields, measuring width and height before drawing and retaining native fallbacks. It does not use the large Inter bitmap as a small clock or claim a watch-wide Inter installation. Its font requests follow the existing 0.80 to 1.35 device scale. Digital and the existing Inter resource retain their earlier admission and fallback contracts.

The analog dial uses original baton markers, a double marker at twelve, a quiet minute track and distinct hour and minute hands. The hour hand advances with the minutes. In the retained Analog layout, date sits above the center, data below it and charge near six. Hands draw last with an opposing edge, so a hand can temporarily obscure an inner reading. Digital remains available for a layout without hands. There is no seconds hand or added one-second timer.

Hybrid puts exact digital time in an upper register, date above it, Weather and Steps below the center and charge near six. Both complete hands draw before the text. One-pixel glyph halos use a transparent text background, preserving the readings without painting a broad rectangle across the hand. The hands can still cross individual glyphs. Full sweep geometry, host comparisons and representative native simulator observations answer different questions; no universal readability or physical-display claim follows from this ordering.

Active and always-on share the same larger base marker and hand vertices around the existing center, 227. The hour markers have an outer radius of 218 pixels, with inner radii of 194 at the cardinal positions and 200 elsewhere. Opposite cardinal outer vertices span 436 pixels, from coordinate 9 to 445. The active minute track uses radii 215 and 221, giving a nominal 442-pixel outer diameter. Only 48 minute strokes are drawn: each hour-index stroke is omitted so the batons are the major graduations. That track diameter does not describe the baton span or a continuous drawn circle. The hour and minute hand lengths are 130 and 191 pixels. Hybrid adds its own text bands and neutral facets. The retained Analog and Digital text bands, opposing active hand edge, original font resources, device font scale and information providers remain separate preserved contracts. Hands can still pass over inner information.

The visual direction uses a clear time hierarchy and restrained secondary information. ## Information fields

Analog and Digital each independently select Weather, Steps or Body Battery. Their defaults remain Weather on the left and Steps on the right. The persistent `leftData` and `rightData` values use 0, 1 and 2 respectively. Missing or invalid choices fall back to that field's default. Hybrid always shows Weather and Steps without changing these saved legacy choices. Selecting Hybrid unregisters an unused Body Battery subscription; returning to a legacy layout restores subscriptions for its displayed fields.

- Weather reads Garmin's cached current conditions. It converts Celsius once when Fahrenheit is selected and shows the cache age. Observations older than two hours are marked stale by this face's policy. This is not a promise about Garmin's refresh interval. Missing, future or invalid timestamps remain age unknown.
- Steps reads the native activity-monitor count and an available positive goal. A real zero remains zero. Missing or invalid data shows an unavailable state.
- Body Battery reads the native Garmin complication provider. It subscribes only when a field selects it, retains the callback while subscribed and unregisters it when deselected or the app stops. It remains labeled as a Garmin score, separate from the watch's charge.

The manifest adds only `ComplicationSubscriber` for this data access. It does not request direct sensor or sensor-history access. The APIs are described in Garmin's [Complications](https://developer.garmin.com/connect-iq/api-docs/Toybox/Complications.html), [ActivityMonitor](https://developer.garmin.com/connect-iq/api-docs/Toybox/ActivityMonitor.html) and [Weather](https://developer.garmin.com/connect-iq/api-docs/Toybox/Weather.html) references. Always-on and Off drawing return before active field reads.

Every drawing clears the previous frame. Watch-face low-power callbacks and the actual display mode gate the sparse view. An off display or mismatched geometry produces black. Unknown modes use the sparse view. Both always-on paths return before active font selection, information-provider reads and battery formatting.

Analog and Hybrid always-on draw the thirteen hour-baton outlines, including the double marker at twelve, both hand outlines and a small outlined center. They use the same enlarged base vertices as the active dial, with one shared translation. The four minute phases are `(-2, -2)`, `(2, -2)`, `(2, 2)` and `(-2, 2)`, including the wrap from minute 59 to 00. Each step moves four pixels. Strokes are one pixel in the neutral Obscur border color on black. The minute track, active text and information fields are omitted. No filled hands, white background, seconds, animation or added timer is used. Invalid inputs produce no drawing.

Digital always-on retains the original function. Its time is clipped to at most 192 by 64 pixels, moves among the original bounded minute positions and has no date, battery, label or bright active background. It tries a smaller platform font if the first does not fit. If neither fits, it remains black until a later update rather than spilling outside the bound.

The admitted Digital rectangle is a conservative source-level bound below 10% of the round visible area, even if every admitted pixel were lit. Overlapping edge allowances are counted repeatedly. These checks do not measure Garmin's rasterized pixels or runtime luminance.

The active Obscur canvas and separate always-on canvas are both `#000000`. Their rendering paths remain distinct. The preserved desktop packages retain their earlier `#090909` canvas. Garmin's current [watch-face guidance](https://developer.garmin.com/connect-iq/articles/user-experience-guidelines/Watch_Faces.html) limits AMOLED AOD to minute updates and 10% of available display pixels. Its [entry-point guide](https://developer.garmin.com/connect-iq/articles/user-experience-guidelines/Entry_Points.html) distinguishes two protection generations.
