# Clair and Obscur watch-face candidate

This Connect IQ watch face targets `fenix9pro47mm`, the fēnix 9 Pro 47 mm AMOLED. Version 0.10.0 Hybrid revises the original black diver composition around a compact day aperture at three and a small digital clock below the pivot. A shallow filled bezel, original radial line numerals, eight circular indices, cardinal batons, an inward triangle at twelve and a divided hour hand preserve the analog hierarchy. Full calendar context, weather, steps and watch battery remain active information. The numbered scale is a visual reference, not an interactive timer. The source uses the existing monochrome palette without changing desktop packages, saved layout meanings or the separate Analog/Digital modes.

The normal and diagnostic 0.10.0 programs compile for the exact target. The focused host suite ran 60 tests, with 58 passed, two explicit original-font regeneration skips and no failures. All 42 annotated target groups compiled; zero executed. Two private host SVG compositions were compared with retained 0.9.0 SDK images. The lower-clock arrangement was selected as the stronger starting hierarchy. Those approximate host images are not renders of the Monkey C program or evidence of native font fit. Current target rendering and runtime qualification remain deferred while the shared PC is in use. Earlier SDK observations retain their own version-specific scope.

The [preserved 0.9.0 qualification](#preserved-090-qualification) and preserved version sections distinguish source checks, actual simulator execution, file transfer and physical observations. Compilation alone does not establish native rendering, settings persistence, runtime memory, physical-watch installation, store acceptance or battery life. All earlier programs and desktop package identities remain separate.

## Supported setup

Use Garmin's [SDK download](https://developer.garmin.com/connect-iq/sdk/) and [Getting Started](https://developer.garmin.com/connect-iq/connect-iq-basics/getting-started/) instructions. Complete the official SDK Manager's private Garmin Connect sign-in, acquire SDK 9.2.0 and the exact `fenix9pro47mm` device package with fonts, and select that SDK as active. The inspected official setup does not establish a fresh noninteractive download route. Do not substitute an unofficial downloader, guessed endpoint or another device identifier.

The [command-line setup](https://developer.garmin.com/connect-iq/reference-guides/monkey-c-command-line-setup/) requires Java 11 or newer. A verified vendor runtime archive can be kept local to the build without changing system PATH. The build command below selects its Java directory for the compiler process only.

Garmin also requires an RSA 4096-bit developer key to sign compiled programs. Keep the private key outside this repository and its build outputs. Follow Garmin's key-generation instructions and retain the key privately for future updates. Do not commit, copy into a source archive or export an existing key for this build.

## Generate and compile

The palette generator maps the validated semantic roles in `tokens-monochrome.json` to Monkey C constants. It does not modify the desktop tokens or `dist/`. Explicit `--tokens tokens.json --output NEW_FILE` can generate the earlier palette colors for inspection without replacing the current generated source.

```powershell
python -m themeforge.garmin
python -m themeforge.garmin --check
python garmin/build.py --sdk C:/path/to/installed-sdk --java-bin C:/path/to/runtime/bin --key C:/private/developer_key.der --output-dir outputs/garmin-build-01
```

Use a new output directory for each build. The wrapper preserves previous output, checks the generated palette, selects only `fenix9pro47mm`, captures compiler diagnostics and records a nonempty program's checksum after a successful compiler result. Its Java process uses headless mode, limits the heap to 1 GiB and sets the JVM's active processor count to two. It does not download packages, generate keys, install an app or launch a simulator. A program's file size is not its runtime memory use.

Add `--tests` to compile the annotated Monkey C tests. That includes tests in a program without running them. Garmin's [unit-test framework](https://developer.garmin.com/connect-iq/core-topics/unit-testing/) executes in its simulator. Simulator execution requires a separately suitable environment and must not silently launch on an occupied desktop.

## Appearance and rendering

The system Watch Face configuration menu offers Appearance and Layout. The persistent `appearance` property remains 0 for Clair and 1 for Obscur, with Obscur as the default. The `layout` property preserves 0 for Analog, 1 for Digital and 2 for Hybrid. Hybrid remains the new-install and invalid-value fallback. Existing valid saved values are retained until deliberately changed. The existing Layout subtitle includes the program version. Analog and Digital show Left data and Right data controls. Hybrid instead shows its date-format control because its Weather and Steps fields are fixed. The legacy data properties are not overwritten. Invalid menu selections do not replace a saved choice. Choosing an item saves it and returns to the face. Back cancels the highlighted choice. Settings changes request a fresh drawing. The [preserved 0.9.0 qualification](#preserved-090-qualification) records actual Appearance switching and one normal SDK restart before property repair. The [preserved 0.8.0 qualification](#preserved-080-qualification) retains its date-menu and earlier restart observations. Neither establishes permanent or physical-watch persistence.

Time follows the device's 12/24-hour preference. Hybrid places AM/PM beside digital time when needed. The legacy layouts keep it on their compact calendar line. Every update captures one `Time.Moment`; numeric and localized Gregorian information come from that same moment. Hybrid uses the device/language-dependent abbreviated weekday and month, with Day Month, Month Day or an ISO date selected by the existing `hybridDateFormat` property. The reviewed public API does not expose the device's date-order preference, so this does not claim to mirror one automatically. Missing localized names fall back to an unambiguous ISO date. Analog and Digital retain their compact English date. See [Gregorian.Info](https://developer.garmin.com/connect-iq/api-docs/Toybox/Time/Gregorian/Info.html) for native format semantics.

Battery percentages are truncated to whole percentages. Invalid or unavailable values display `--%`, including the explicit NaN guard retained from the earlier target defect. Hybrid uses `BAT` normally and `CHG` when `System.Stats.charging` is true. That is the supported charger-state indicator, not a measurement of charging current. It remains the watch's charge, separate from Body Battery. Garmin documents charge hysteresis and the [battery and charging attributes](https://developer.garmin.com/connect-iq/api-docs/Toybox/System/Stats.html).

At font scale 1.00, the Digital layout first tries the included Inter Bold clock resource, limited to digits, colon and the invalid-time hyphen. It measures width and height before drawing. Unsupported text or a failed fit falls back to the retained native time candidates. Other font scales use native Bionic Bold time candidates, preserving the continuous platform scale instead of silently holding the bitmap size fixed. Digital values retain Bionic Bold, with Roboto Medium for calendar and battery and Roboto Condensed for field labels and detail. The Analog layout uses Roboto Medium for values, date and charge, with Roboto Condensed for labels and detail. The view reads the device's 0.80 to 1.35 font-scale preference and caches fonts for the selected layout only. It includes scaled platform-font fallbacks when a requested face is unavailable. Every selection measures width and height before clipped drawing. Analog fields choose all three row fonts together so the complete group fits its smaller band. If no measured combination fits, that field stays blank. Legacy glyph fit and unavailable-field visibility still need their own current-version native inspection. The single derived clock atlas and metrics are bundled under the included SIL Open Font License. The original TTF is not bundled. The resource is loaded once outside the update handler and remains cached, including while Analog is selected. Its loaded-memory cost remains unmeasured. Analog supporting text, settings menus and Digital always-on keep Garmin fonts. Analog always-on draws no text. This is a bounded app resource, not a watch-wide font installation.

Hybrid requests native Roboto Medium for dynamic time, period, calendar, day, values and battery, with Roboto Condensed for restrained branding and secondary status. Time and AM/PM have disjoint measured clips below the pivot. The day aperture measures its own font. Weather and steps use two rows whose status and value must fit together; the legacy three-row fitter remains unchanged. Weather keeps units and distinct CACHE, STALE, AGE UNKNOWN and NO WEATHER states. Steps keeps its full count and a STEPS label, without the former Hybrid goal row; Analog and Digital retain their selectable fields and goal detail. Failed fits use an unavailable marker instead of inventing a reading. Font candidates include smaller sizes, but actual target fit at ordinary and enlarged scale remains uninspected for 0.10.0. Hybrid does not use the Digital Inter bitmap or claim a watch-wide font installation.

The analog dial uses original baton markers, a double marker at twelve, a quiet minute track and distinct hour and minute hands. The hour hand advances with the minutes. In the retained Analog layout, date sits above the center, data below it and charge near six. Hands draw last with an opposing edge, so a hand can temporarily obscure an inner reading. Digital remains available for a layout without hands. There is no seconds hand or added one-second timer.

Hybrid prints calendar context and restrained own-brand text above the pivot, a digital clock below it, weather and steps in two lower columns, and charge near six. A light day aperture at three replaces that active baton. Ordinary information is drawn before the hands, so a crossing hand can obscure it temporarily. Only the day and same-canvas digital clock clear a rectangle above the hands. These rectangles do not intersect the guarded circular hour head in the source geometry. This does not promise that the whole head is always visible: the later-painted minute hand can overlap it, and a protected field can cover part of a stem or tip. The active view uses no glyph halos to fragment the hand contours. Actual target rasterization and wrist readability remain separate checks.

## Information fields

Analog and Digital each independently select Weather, Steps or Body Battery. Their defaults remain Weather on the left and Steps on the right. The persistent `leftData` and `rightData` values use 0, 1 and 2 respectively. Missing or invalid choices fall back to that field's default. Hybrid always shows Weather and Steps without changing these saved legacy choices. Selecting Hybrid unregisters an unused Body Battery subscription; returning to a legacy layout restores subscriptions for its displayed fields.

- Weather reads Garmin's cached current conditions. It converts Celsius once when Fahrenheit is selected and shows the cache age. Observations older than two hours are marked stale by this face's policy. This is not a promise about Garmin's refresh interval. Missing, future or invalid timestamps remain age unknown.
- Steps reads the native activity-monitor count and an available positive goal. A real zero remains zero. Missing or invalid data shows an unavailable state.
- Body Battery reads the native Garmin complication provider. It subscribes only when a field selects it, retains the callback while subscribed and unregisters it when deselected or the app stops. It remains labeled as a Garmin score, separate from the watch's charge.

The manifest adds only `ComplicationSubscriber` for this data access. It does not request direct sensor or sensor-history access. The APIs are described in Garmin's [Complications](https://developer.garmin.com/connect-iq/api-docs/Toybox/Complications.html), [ActivityMonitor](https://developer.garmin.com/connect-iq/api-docs/Toybox/ActivityMonitor.html) and [Weather](https://developer.garmin.com/connect-iq/api-docs/Toybox/Weather.html) references. Always-on and Off drawing return before active field reads.

Every drawing clears the previous frame. Watch-face low-power callbacks and the actual display mode gate the sparse view. An off display or mismatched geometry produces black. Unknown modes use the sparse view. All three always-on paths return before active font selection, information-provider reads and battery formatting.

Analog always-on retains its thirteen hour-baton outlines, including the double marker at twelve, both hand outlines and a small outlined center. Hybrid has its own sparse path with eight circular indices, the three cardinal batons, twelve triangle, separate hour stem and tip, divided circular head and minute-hand outline. It clears the hollow hour head on black before drawing its rim and three spokes, so hidden join edges do not run through the head. Both Analog and Hybrid translate their own geometry through the four minute phases `(-2, -2)`, `(2, -2)`, `(2, 2)` and `(-2, 2)`, including the wrap from minute 59 to 00. Each step moves four pixels. Strokes use the neutral Obscur border color on true black. Active text, information fields, bezel numerals and minute tracks are omitted. There is no bright active background, filled luminous hand, seconds, animation or added timer. Invalid inputs produce no drawing.

Digital always-on retains the original function. Its time is clipped to at most 192 by 64 pixels, moves among the original bounded minute positions and has no date, battery, label or bright active background. It tries a smaller platform font if the first does not fit. If neither fits, it remains black until a later update rather than spilling outside the bound.

Garmin's current [compatible-device table](https://developer.garmin.com/connect-iq/compatible-devices/) lists the exact target as a 454 by 454 round AMOLED display at API level 6.0. The installed exact-target metadata confirms the geometry and declares a 131,072-byte watch-face memory limit. The admitted Digital rectangle is a conservative source-level bound below 10% of the round visible area, even if every admitted pixel were lit. Their larger five-pixel edge allowance bounds at most 11,079 pixels against 161,892 ideal round pixels, about 6.85%, even when treated as full white and repeatedly counting overlaps. Hybrid now has separate outline-budget and round-bound checks for its new shapes. These source calculations do not measure Garmin's rasterized pixels, runtime luminance or physical power use.

The active Obscur canvas and separate always-on canvas are both `#000000`. Their rendering paths remain distinct. The preserved desktop packages retain their earlier `#090909` canvas. Garmin's current [watch-face guidance](https://developer.garmin.com/connect-iq/articles/user-experience-guidelines/Watch_Faces.html) limits AMOLED AOD to minute updates and 10% of available display pixels. Its [entry-point guide](https://developer.garmin.com/connect-iq/articles/user-experience-guidelines/Entry_Points.html) distinguishes two protection generations.
