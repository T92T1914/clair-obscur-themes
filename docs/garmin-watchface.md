# Clair and Obscur watch-face candidate

This separate Connect IQ watch-face source targets `fenix9pro47mm`, the fēnix 9 Pro 47 mm AMOLED. Version 0.6.0 adds a matching low-power analog view. It retains the active analog dial and digital layout, including the Inter Bold digital clock resource from 0.5.0. Both active layouts show local time, a compact English weekday and date, two selectable information fields and watch battery percentage. Clair and Obscur use `tokens-monochrome.json`: white backgrounds with black primary lettering in Clair, black backgrounds with white primary lettering in Obscur, and neutral gray for supporting information. Earlier programs remain separate and unchanged. Always-on uses true black: Analog retains thin hour markers and hands, while Digital retains the original small time-only view. A fully off display remains black.

The preserved 0.4.0 normal and test-enabled programs compiled for the exact target with Connect IQ SDK 9.2.0 and device package `ee244507b073c52779d26e77dc69b690d79098bd`. The test build includes 20 annotated test groups. They have not run for 0.4.0. The separate 0.3.0 and 0.2.0 simulator results remain below. Compilation does not establish native rendering, settings persistence, runtime memory, physical-watch installation, store acceptance or battery life. Earlier local candidates and all desktop package identities remain separate.

Garmin also requires an RSA 4096-bit developer key to sign compiled programs. Keep the private key outside this repository and its build outputs. ## Generate and compile

The palette generator maps the validated semantic roles in `tokens-monochrome.json` to Monkey C constants. It does not modify the desktop tokens or `dist/`. Explicit `--tokens tokens.json --output NEW_FILE` can generate the earlier palette colors for inspection without replacing the current generated source.

```powershell
python -m themeforge.garmin
python -m themeforge.garmin --check
python garmin/build.py --sdk C:/path/to/installed-sdk --java-bin C:/path/to/runtime/bin --key C:/private/developer_key.der --output-dir outputs/garmin-build-01
```

Use a new output directory for each build. The wrapper preserves previous output, checks the generated palette, selects only `fenix9pro47mm`, captures compiler diagnostics and records a nonempty program's checksum after a successful compiler result. Its Java process uses headless mode, limits the heap to 1 GiB and sets the JVM's active processor count to two. It does not download packages, generate keys, install an app or launch a simulator. A program's file size is not its runtime memory use.

Add `--tests` to compile the annotated Monkey C tests. That includes tests in a program without running them. Garmin's [unit-test framework](https://developer.garmin.com/connect-iq/core-topics/unit-testing/) executes in its simulator. Simulator execution requires a separately suitable environment and must not silently launch on an occupied desktop.

## Appearance and rendering

The system Watch Face configuration menu offers Appearance, Layout, Left data and Right data. Its appearance submenu and the declared application setting use the same persistent `appearance` property: 0 for Clair and 1 for Obscur. The default is Obscur. Layout uses its own persistent `layout` property: 0 for Analog, the new default, and 1 for Digital. Missing or invalid layout values use Analog. Existing appearance and information choices keep their property names and values. Invalid menu selections do not overwrite a saved choice. Choosing an item saves it and returns to the face. Back cancels the highlighted choice. Settings changes request a fresh drawing. These are source contracts pending current-version native interaction and restart checks.

Time follows the device's 12/24-hour preference, with AM/PM on the compact calendar line when needed. Date and time share one local Gregorian snapshot so an update cannot mix opposite sides of midnight. Battery percentages are truncated to whole percentages, and invalid or unavailable values display `--%`. The target runtime required an explicit NaN rejection before numeric conversion. That reproduced defect and its regression remain part of the candidate.

At font scale 1.00, the digital layout first tries the included Inter Bold clock resource, limited to digits, colon and the invalid-time hyphen. It measures width and height before drawing. Unsupported text or a failed fit falls back to the retained native time candidates. Other font scales use native Bionic Bold time candidates, preserving the continuous platform scale instead of silently holding the bitmap size fixed. Data values retain Bionic Bold, with Roboto Medium for calendar and battery and Roboto Condensed for field labels and detail. The analog layout uses Roboto Medium for values, date and charge, with Roboto Condensed for labels and detail. The view reads the device's 0.80 to 1.35 font-scale preference and caches fonts for the selected layout only. It includes scaled platform-font fallbacks when a requested face is unavailable. Every selection measures width and height before clipped drawing. Analog information fields choose all three row fonts together so the complete group fits its smaller band. If no measured combination fits, that field stays blank. Exact glyph fit and unavailable-field visibility still need current-version native inspection. The single derived clock atlas and metrics are bundled under the included SIL Open Font License. The original TTF is not bundled. The resource is loaded once outside the update handler and remains cached, including while Analog is selected. Its loaded-memory cost remains unmeasured. Analog supporting text, settings menus and Digital always-on keep Garmin fonts. Analog always-on draws no text. This is a bounded app resource, not a watch-wide font installation.

The analog dial uses original baton markers, a double marker at twelve, a quiet minute track and distinct hour and minute hands. The hour hand advances with the minutes. Date sits above the center, information fields below it, and watch charge near six. Hands draw last with an opposing edge so time remains legible when a hand crosses text. Inner readings can be temporarily obscured by a hand. Digital remains available when uninterrupted data reading matters more than an analog dial. There is no seconds hand or added one-second timer.

The visual direction uses a clear time hierarchy and restrained secondary information. The original digital references included the [MoMA Max Bill kitchen clock](https://www.moma.org/collection/works/139247), [Braun AW10](https://braun-clocks.com/products/aw-10-classic-watch-with-leather-strap) and [Hamilton Khaki Field](https://www.hamiltonwatch.com/en-us/h69439931-khaki-field-mechanical.html). The analog design also draws on the legibility priorities described for the [Rolex Explorer](https://www.rolex.com/watches/explorer/features), the simple indices of the [Oyster Perpetual](https://www.rolex.com/watches/oyster-perpetual/features), [Omega's black-dial Aqua Terra](https://press.omegawatches.com/a-classic-in-three-sizes-introducing-the-seamaster-aqua-terra-black-dial/) and the restrained display of the [IWC Mark XX](https://www.iwc.com/us-en/watches/pilot-watches/iw328201-pilots-watch-mark-xx). These are manufacturer descriptions of design features, not a comparative legibility study. The face uses its own geometry and no manufacturer logos or dial artwork. No universal best-design or endorsement claim is made.

## Information fields

Each field independently selects Weather, Steps or Body Battery. The defaults are Weather on the left and Steps on the right. The persistent `leftData` and `rightData` values use 0, 1 and 2 respectively. Missing or invalid choices fall back to that field's default.

- Weather reads Garmin's cached current conditions. It converts Celsius once when Fahrenheit is selected and shows the cache age. Observations older than two hours are marked stale by this face's policy. This is not a promise about Garmin's refresh interval. Missing, future or invalid timestamps remain age unknown.
- Steps reads the native activity-monitor count and an available positive goal. A real zero remains zero. Missing or invalid data shows an unavailable state.
- Body Battery reads the native Garmin complication provider. It subscribes only when a field selects it, retains the callback while subscribed and unregisters it when deselected or the app stops. It remains labeled as a Garmin score, separate from the watch's charge.

The manifest adds only `ComplicationSubscriber` for this data access. It does not request direct sensor or sensor-history access. The APIs are described in Garmin's [Complications](https://developer.garmin.com/connect-iq/api-docs/Toybox/Complications.html), [ActivityMonitor](https://developer.garmin.com/connect-iq/api-docs/Toybox/ActivityMonitor.html) and [Weather](https://developer.garmin.com/connect-iq/api-docs/Toybox/Weather.html) references. Always-on and Off drawing return before active field reads.

Every drawing clears the previous frame. Watch-face low-power callbacks and the actual display mode gate the sparse view. An off display or mismatched geometry produces black. Unknown modes use the sparse view. Both always-on paths return before active font selection, information-provider reads and battery formatting.

Analog always-on draws the thirteen hour-baton outlines, including the double marker at twelve, both hand outlines and a small outlined center. They use the existing active vertices and one shared translation. The four minute phases are `(-2, -2)`, `(2, -2)`, `(2, 2)` and `(-2, 2)`, including the wrap from minute 59 to 00. Each step moves four pixels. Strokes are one pixel in the neutral Obscur border color on black. The minute track, active text and information fields are omitted. No filled hands, white background, seconds, animation or added timer is used. Invalid inputs produce no drawing.

Digital always-on retains the original function. Its time is clipped to at most 192 by 64 pixels, moves among the original bounded minute positions and has no date, battery, label or bright active background. It tries a smaller platform font if the first does not fit. If neither fits, it remains black until a later update rather than spilling outside the bound.

The public [device reference](https://developer.garmin.com/connect-iq/articles/device-reference/fenix9pro47mm.html) documents a 454 by 454 round display and a 131,072-byte watch-face memory budget. The installed exact-target metadata confirms those values. The admitted Digital rectangle is a conservative source-level bound below 10% of the round visible area, even if every admitted pixel were lit. The host geometry check counts pixel centers within an ideal circle and obtains an upper bound of about 7.59%. Analog has a separate outline-geometry budget. Source-bound host checks cover all 720 analog minute positions and four shift phases, include stroke and antialiasing headroom, and bound white-pixel coverage against the same visible round area. Across those 2,880 geometry cases, the larger five-pixel edge allowance bounds at most 10,529 pixels against 161,892 visible round pixels, about 6.51%, even when treated as full white. Overlapping edge allowances are counted repeatedly. These checks do not measure Garmin's rasterized pixels or runtime luminance.

The current watch Obscur canvas and the separate always-on canvas are both `#000000`. Their rendering paths remain distinct. The preserved desktop packages retain their earlier `#090909` canvas. Garmin's [detailed AMOLED guidance](https://developer.garmin.com/connect-iq/articles/connect-iq-faq/How_Do_I_Make_a_Watch_Face_for_AMOLED_Products.html) distinguishes older pixel-protection rules from later-device luminance rules. Its [System 7 announcement](https://forums.garmin.com/developer/connect-iq/b/news-announcements/posts/welcome-to-system-7) describes the API 5 and later rule as below 10% of full-screen luminance. The exact target is API 6.0. Conservative white-pixel bounds avoid relying on an undocumented luminance-weighting formula. The translated outlines follow the recommendation to move static elements gently; translation alone does not prove every physical pixel has a dark interval. Firmware enforcement, protection behavior, native pixels and power use still need target observations.

## Inter clock resource

The resource uses twelve glyphs from Inter Bold: digits, colon and hyphen. Glyphs retain their original proportions. This candidate does not claim tabular-number shaping. The provenance file records the exact source-font digest, family and version, resource hashes and rasterizer versions. The font license remains separate from the project license.

The explicit-input generator is `garmin/generate_clock_font.py`. Its help describes fresh output and check modes. Supply the exact licensed source font and license identified in `resources/fonts/provenance.json`. Regeneration requires Pillow and fontTools in the local build environment. Normal builds consume the committed resource and do not require font discovery, downloads or those Python libraries. No font is fetched during preview generation or application use.
