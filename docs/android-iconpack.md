## Apply through the actual consumer

Both packs have minimum API 26 and target API 36 and declare no permissions. The identity table above distinguishes Clair Icons 0.1.6/code 7 from Obscur Icons 0.1.17/code 18. Installation still requires the device owner's approved Android installation path. Preserve the accepted Obscur app and working icon-theme selection when trying the separate Clair package. Do not change security settings or replace an unrelated application to force installation.

For later native acceptance, first record the installed Android, launcher and Theme Park/module versions, both display layouts, installed pack identities and current theme selection. Keep the working theme and home-screen arrangement. After an approved installation, open each installed pack and check its exact package/artwork label. Opening the app or pressing Check icon coverage does not apply a theme.

Open the installed Theme Park version's Icon editor and Iconpack chooser. Check whether each separate pack is recognized. For the intended appearance, inspect a new separate icon-theme draft before saving or applying it. A saved Theme Park theme may require regeneration, and installing or updating an APK does not establish that assignments or an existing saved theme refreshed. Retain the working theme and previous selection for restoration.

Inspect mapped apps, actual masks, cropping, labels, folders, app drawer and cover and inner displays. Check switching, ordinary restart and restoration through supported controls. Installed coexistence, recognition, assignment and persistence require actual device observation. If the chooser does not recognize a pack, retain that result without treating compiled-package checks as phone acceptance.

Preserve the default keyboard, languages, learned words, number row, layouts, key borders, saved themes and system font. Samsung Keyboard/Keys Cafe and Gboard have separate customization paths. Existing Gboard backgrounds cannot set native key geometry, special-key colors, suggestions or live glyphs. The pack supplies explicit component-to-drawing mappings. It does not guess a `MainActivity`, replace every unmatched app with one generic picture, or promise to cover every app in a store. Dynamic icons and launcher-specific extensions are not implemented. An app update or alias change can leave a previously known package unmapped. ## Local coverage check

The launchable app explains how to apply the pack and offers Check icon coverage. That button compares visible launcher components only within the public supported package list. The manifest's narrow package queries are generated from that same list. It does not request `QUERY_ALL_PACKAGES` or enumerate unrelated packages.

The check displays counts and any visible supported components lacking an exact mapping. It does not upload, log or save those observations, and it starts no persistent service. No visible launcher entry can mean a package is absent or has no visible entry. The result cannot prove which pictures Theme Park applied. Preserve any device observations privately and use only the missing non-sensitive component facts needed for a deliberate later mapping change.

A completed report is retained only as an immutable in-memory string through Android's optional [nonconfiguration retention callback](https://developer.android.com/reference/android/app/Activity#onRetainNonConfigurationInstance()). An eligible Activity recreation displays that snapshot without another package query. During an explicit rescan, the last completed snapshot remains available until the live scan succeeds or fails. A failure clears that snapshot. The destroyed Activity rejects its delayed callback, leaving the successor unchanged. A first scan still in flight, a cold launch or process loss starts with the original empty prompt and enabled scan button. No view, Activity, worker or serialized inventory is retained.

The focused JVM regression compiles the actual Activity source against synthetic Android APIs. Its 29 checks cover completed and in-flight recreation, delayed callbacks, fresh scans, failures and cold/process-loss fallback. This reproduces report loss in the earlier source and checks the correction's app logic. The host supplies lifecycle delivery, so it does not qualify Android's callback behavior, physical folding, launcher recognition or phone application. Android's [UI-state guidance](https://developer.android.com/topic/libraries/architecture/saving-states) distinguishes configuration recreation from process death; this transient report is deliberately not restored after process loss.

The public source snapshot explicitly includes the app, build command, mapping table and license notices. SDKs, signing keys, compiled APKs and local build outputs stay outside that inventory. Existing desktop packages, SVG archives and release gates are unchanged.
